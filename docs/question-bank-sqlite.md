# 题库 SQLite 读取与性能边界

题库正文的运行时数据源为 `/userdata/hyz-things/question-bank.db`。

## 读取规则

- 试卷目录只读取 `PaperSummary`，不传输和反序列化每份试卷的完整题号、材料及分类数组。
- 整卷阅读、套卷训练、模块训练、错题与收藏使用已同步的 SQLite 正文、选项和材料。
- 数据库内容缺失、损坏或哈希不一致时，按应用错误返回；运行时不回退打开 Markdown。
- Markdown 仍用于显式同步导入；源文件的变化在同步后进入数据库。图片继续通过固定、校验过的资源接口读取。
- 已保存练习保留来源题号和哈希。内容变化时不把新题答案用于旧练习解析；存储错误不把练习误判成不可评分后提交。

## 查询与写入范围

- 单份试卷通过 ID 查找，避免每次操作加载完整目录。
- 模块和集合开练只读取已选题号；工作区、交卷和解析各按该次练习的题号批量读取，材料通过引用主键查询。
- 保存答案仅读取当前题并更新一个 `practice_items`。同一事务用 revision、active、paused 和题号/位置校验保护会话，使用 `json_set` 更新对应答案和版本；提交成功后才确认保存。
- 交卷保留整场评分、attempt 和错题进度更新。保存一题时不会执行这些交卷写入。
- 收藏和错题查询从对应状态表开始，按主键关联题目；不先遍历全部题目再判断是否收藏或待复练。
- 模块聚合和候选题查询先物化符合条件的试卷，减少每道题重复解析试卷 metadata JSON。已作答状态继续使用现有 covering index。
- 分类投影使用 `(paper_id, module, category, number, id)` 覆盖索引，避免为计数读取大的正文记录。此纯附加索引在初始化时幂等创建，保留原有四个迁移版本，使上一版 ELF 可以重新打开数据库；不改变历史、收藏或答案。

## 板端只读诊断

2026-11-03，使用与应用相同的 SQLite 3.46.0 静态库，以 `SQLITE_OPEN_READONLY` 打开设备数据库，仅输出聚合计数及耗时；临时诊断程序已从设备清理。738 份 active/primary 试卷、86,545 个题位，全部题位的 stem 已填充。

加入覆盖索引之前的单次抽测：原模块聚合 2,868.261 ms；先筛选试卷的聚合 1,031.587 ms。两者均返回 32 个分类组。这是 SQL 执行抽测，未包含 HTTP 和浏览器时间，且不同运行的页缓存、设备负载可能影响结果。

## 可重复的主机模拟观察

2026-11-03，在主机 Python SQLite 3.37.2 的内存库中使用项目 migration 造数。以下为五次执行的中位数，表示查询计划差异，不能代表板端 HTTP 延迟。

收藏/错题样本为 400 卷、40,000 题，状态表各 801 行，包含无效与孤立状态。改写前后的 48 组筛选完整有序结果一致：

| 查询 | 全题目起步 | 状态表起步 |
| --- | ---: | ---: |
| 错题浏览 | 53.829 ms | 1.256 ms |
| 收藏浏览 | 49.052 ms | 1.764 ms |

模块样本为 400 卷、每卷 100 题、100,000 条练习题记录；试卷 metadata 含题号和分类数组，平均 6,552 UTF-8 字节。12 组筛选的 catalog 与 96 组候选题完整有序结果一致：

| 查询 | 重复解析试卷 JSON | 先筛选试卷 |
| --- | ---: | ---: |
| 全范围模块聚合 | 232.413 ms | 50.765 ms |
| 年份和地区筛选聚合 | 200.357 ms | 21.584 ms |
| 全范围模块抽题 | 26.359 ms | 8.687 ms |
| 筛选后模块抽题 | 26.397 ms | 6.004 ms |

Rust 应用使用的 SQLite 版本与 Python 样本可能不同；磁盘提交、连接排队、网络和浏览器渲染需独立验证。此轮保持数据库提交与持久化语义。
