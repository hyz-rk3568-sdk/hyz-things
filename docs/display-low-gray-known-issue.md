# RK3568 MIPI LCD 低灰阶左右亮度异常

## 状态

**已知问题，停止继续处理。**

截至 2026-08-08，ATK 5.5 英寸 1080×1920 MIPI-DSI 屏在低亮度像素下会出现固定的左右亮度/色偏分界。该问题不阻塞当前产品 SDK 的构建、Wayland、Flutter 或 recovery-free OTA 流程，但不应被误判为 Flutter 页面渲染错误。

不要在没有新面板资料、原厂寄存器表或可替换硬件进行 A/B 对照的情况下继续试改像素时钟、HX8399 Gamma 或 GIP 参数。

## 稳定软件基线

- 面板目标：`rk3568-atk-evb1-mipi-dsi-1080p`
- 分辨率：1080×1920
- 像素时钟：121 MHz
- DRM 报告刷新率：约 54 Hz
- HX8399 扫描配置：原 ATK `D6` 映射与 `CC 04`
- Weston 扫描缓冲：线性 `XR24`，无 Flutter direct scanout/AFBC
- 已知稳定 recovery-free OTA：
  - 本地文件：`output/display-audit/upgrade-121mhz-stable.fw`（生成物，不提交）
  - SHA-256：`c3c4ddb0f84fdaa51dde08f49112ad24a1847937fc63b44edbfc4fe67b14da37`
  - boot SHA-256：`8708b031444cf162df5a5fe58de150d50f7c84818131aace5256ea76599b6039`
- recovery 基线 SHA-256：`9778353401cf31b6bdca54fd1e5dd59a7a0983d9b32488eb89e3f974f036e363`

这些哈希只用于本次本地诊断记录；重新构建会产生不同时间戳和镜像哈希。

## 可重复现象

Flutter 示例页面使用近黑背景 `RGB(19,19,24)`。该颜色在物理 LCD 上会出现与 Flutter 页面相同的右侧偏亮/偏紫区域，而 Weston 截图中的缓冲内容保持完全均匀。

使用临时全屏 Wayland SHM 客户端进行的结果如下：

| 测试颜色 | 物理显示结果 |
| --- | --- |
| 纯黑 `RGB(0,0,0)` | 正常，无可见分界 |
| 纯白 `RGB(255,255,255)` | 正常 |
| 满亮红、绿、蓝 | 正常 |
| 50% 灰 `RGB(128,128,128)` | 正常 |
| Flutter 背景 `RGB(19,19,24)` | 出现右侧亮度/色偏分界 |
| 低亮红 `RGB(19,0,0)` | 出现同类分界 |
| 低亮绿 `RGB(0,19,0)` | 出现同类分界 |
| 低亮蓝 `RGB(0,0,19)` | 出现同类分界 |

Recovery 阶段还观察到明显的左黑右白现象。普通 Weston 界面未观察到固定分界。

## 已确认的边界

- Flutter、Weston 和应用尺寸不是根因。
- DRM/Weston 截图干净，因此异常发生在合成缓冲之后。
- 三个颜色通道都只在低亮度区间复现，不是单一 RGB 通道 Gamma 故障。
- 纯色高亮与中灰均正常，不符合固定半屏损坏或固定背光漏光的典型表现。
- 现象更接近 HX8399 面板的公共源驱动、GIP、反转驱动或低灰阶模拟电压配置与当前面板不完全匹配；没有面板原厂寄存器表时无法安全确定具体寄存器。

## 已排除的实验

### 136 MHz / 约 60 Hz

将 1080p 时序改为 136 MHz 后：

- 右侧异常没有改善；
- 内核出现 `rockchip-vop2 ... POST_BUF_EMPTY irq err at vp1`；
- 已回退至 121 MHz；
- 回退后 `POST_BUF_EMPTY=0`。

因此不要再次使用该 136 MHz 时序。

### HX8399 `D6 + CC08` 配对

曾将原 ATK 配对：

```text
D6 ... 20 21 02 03 04 05 06 07 00 01 ...
CC 04
```

成对替换为公开 HX8399 参考中的：

```text
D6 ... 20 21 06 07 00 01 02 03 04 05 ...
CC 08
```

测试结果是低灰阶异常没有改善，且肉眼观察更明显。该改动已从内核源码撤销，并通过 recovery-free OTA 刷回稳定固件。不要单独修改 `CC` 或再次应用这一配对。

## 旧 Qt 固件参考

旧的正常 Qt 镜像使用 Linux 4.19.232，并在提取的活动 DTB 中选择了 720×1280、65 MHz、HX8394 初始化序列。当前产品使用 Linux 5.10.160 和 HX8399 1080p 配置。两者不是可直接逐项移植的同一显示配置。

## 停止条件与后续建议

本问题按产品决定停止继续处理。后续只有在至少满足一项时才建议重新打开：

1. 获得这块具体 5.5 英寸模组的原厂 HX8399 初始化表和电压/Gamma/GIP说明；
2. 使用另一块同型号屏或另一块载板完成硬件 A/B 对照；
3. 能在同一块屏上复现一份确认正常的 1080p HX8399 固件；
4. 有示波器或 MIPI 分析条件验证电源、复位、lane 信号和低灰阶反转驱动。

在此之前，保留 121 MHz 和原 ATK `D6 + CC04` 配置，不再通过盲试寄存器解决该问题。

## 最终审计备注

稳定回退 OTA 已完成并回到主系统。本地内核对 `rk3568-lcds.dtsi` 的实验差异已完全撤销，只保留 manifest 预期生成的未跟踪链接 `sdk/kernel/make.sh -> kernel_build.sh`。回退后 ADB 数据连接出现间歇性断开，因此最后一次在线 boot/BCB 哈希复读未完成；回退包本身、设备端上传哈希和暂存 BCB 在重启前均已验证。
