# 资料分析全局卡片级 vcnt 调度 V2（2026-10-26）

状态：实现于 `feat/data-analysis-global-vcnt-scheduler`。

## 目标与硬约束
- 每个题型一个逻辑运行队列（错题/知识点同题型合并），按卡片 `vcnt` 升序排列。
- 无分类级公平计数、无指定考点/错题保底、无题型配额。全局最小费用流一次决定每类数量、卡片与材料分配。
- 4 篇×5题；每篇五个不同题型；整卷20个不同 `card_id`。
- 卡片 `selected_count` 是新生成试卷实际选择次数；仅完整新试卷成功写入才加1。历史重做不增加次数或 `vcnt`。
- `vcnt` 是整数虚拟次数，新卡从全局最小值起步；旧 `fair_count` 一次性乘1024迁移。
- 每次成功生成后增量基于本次规划时冻结的已交卷实际作答成绩；若全卷失败则不消耗计数。

## 加权规则
```text
p = (correct + 2) / (answered + 4)
w = clamp(1 + 0.8 * (0.5 - p), 0.7, 1.3)
delta_vcnt = round(1024 / w)
```
历史成绩变更只影响未来的增量，不回溯修改之前的 vcnt。

## 分配网络
- Source→Type 每一单位容量的费用，对应该题型中 vcnt 升序的第 k 张卡，最多四条边。
- Type→Group 每篇一条容量1、费用0的边。
- Group→Sink 每篇容量5、费用0。
- 总流量20，优化目标为最小化选中卡片 vcnt 的总和。
- 相同费用的候选由 task seed 决定可复现的打散顺序。

## 作答与历史
- `data_analysis_results.card_id` 指向原卷题目来源；`was_answered` 只在最终已提交答案非空时为1。
- 没作答绝不算错；重做各自独立计入；修改答案仅以最后已交卷选择为准；重复提交幂等。
- 交卷在写锁保护的事务内冻结答案并记分。
- 历史交卷结果从 `groups_json` 和 `answers_json` 回填，旧卷没有可信 card_id 的不参与卡片正确率。
- 旧分类计数表及卡片 fair_count 列暂时保留供回滚，不再参与出题。

## 范围
- 移除综合训练前端的手选考点操作和服务端选题参数；使用空 JSON POST 请求。
- 不修改普通 Flashcard/FSRS、Markdown、Codex Prompt、原有超时或并发配置。
- Rust 及 Playwright 覆盖全局队列、同篇互斥、最小费用、重做成绩、未答题、幂等与持久化。
