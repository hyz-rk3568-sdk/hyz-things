# 资料分析四选一速算训练 — 实施 Plan（待 Review）

> 日期：2026-10-20
> 状态：仅方案，**未经用户确认不得实现**
> 目标：在 hyz-things 现有「学习」入口扩展资料分析心算训练，不做微信小程序，不要求输入精确计算结果。

## 1. 需求与边界

- 题型优先：三位 ÷ 两位、三位 × 两位；后续可选百分比乘法。优先练 **试商/高位拆乘/截位**，与用户 `flashcards/资料/` 的速算习惯一致。
- 每题只给算式与 **A/B/C/D 四选一**，可直接点选并快速进入下一题；不出现答题输入框。
- **由选项自然决定计算精度**，不显示“保留两位/三位有效数字”的提示，不要求做完整精确运算。
- 可设置 **选项间距**：大间距，如 1.23/1.33/1.43；小间距，如 123/124/125；随机混合模式只随机选项间距，**不**随机指定求解精度。
- 支持 10/20/50 题训练、逐题耗时、正确率、错题回看及计算止步点评；适配 iPad 横竖屏和触摸操作。

## 2. 仓库落点调查（实现前核验）

- 已确认管理门户代码在 `apps/rust/things`，浏览器前端 `src/web/`（Yew/WASM），静态样式 `frontend/`，部署为嵌入式前端；AGENTS.md 要求 Red → Green → Refactor、独立分支 PR。
- **尚未确认**学习页具体路由、组件、复习数据存储及现有测验状态机。编码前先查明并复用，禁止猜测既有 API/数据库表名。
- 若已有学习模块，优先加「学习 → 资料分析 → 速算训练」入口；不存在对应导航层时使用最少一级入口，避免为了该功能重构整体菜单。
- 第一版**前端本地计算出题、判题和会话统计**；持久化优先复用已有学习模块存储。若复用成本高，可先只保存会话内成绩，不引入新的后端 API、SQLite migration、鉴权权限或独立微服务。持久历史记录另列后续迭代。

## 3. 题目及选项生成契约（重点）

1. 基于范围随机整数生成被除数/除数或两个乘数；除数不得为 0，题目难度参数决定数字分布。
2. 使用**精确整数/有理数**作为底层正确值，避免浮点数比较误判。界面可展示小数，但须统一、明确取整/舍入规则。
3. 为每题选择一个「展示精度（选项格式）」及间距档位，然后构造四个**互不相同、严格递增、同单位同小数位数**的备选值，最后洗牌到 A/B/C/D。正确答案必须唯一且位置均匀分布。
4. **判题定义**：计算值按本题选项的展示精度四舍五入后，**恰有一个选项等于该值**。不要拿“离真实数最近”与“精确舍入命中”混为同一套规则。若使用“最接近值”问法，必须另建题型并排除等距情况。
5. **展示精度与间距分离**：`1.23/1.33/1.43` 的间距是 0.10，`123/124/125` 的间距是 1；二者都不表示系统必须提前提示用户需要算几位。用户通过观察选项决定自己的截位策略。
6. 对乘法和除法，按商/积的数量级自然渲染，必要时用等比例单位（例如「×10³」或「万」）并保持四个选项单位一致；避免 `387÷31` 却出现 1.23 这种无单位的数量级错误。
7. 出题器必须限制错误干扰项离谱、跨数量级、不合理负值、重复项、正确答案缺席、边界舍入歧义、答案位置偏置。
8. 用种子随机数/注入 RNG 提供确定性测试，重复抽样统计不同间距下的唯一正确项和位置分布。

## 4. 交互方案

- 练习设置区：勾选题型、间距（大/小/混合）、题量；其他默认值保持简洁。
- 作答区：大字号算式、2×2 大触摸按钮、当题计时。点选后锁定答案，显示正确/错误与一条**高位拆乘或分子三位/分母两位试商**短解；再进入下一题。
- 训练中可结束本轮；结束页展示总用时、平均每题耗时、正确率、按间距分组的正确率和耗时、错题。
- 避免额外动画、无关导航干扰和详细竖式；iPad 可全屏沉浸展示，提供返回学习页入口。

## 5. 分阶段实现与验收（获批后）

### Phase A — 路由/组件落点
- 梳理现有学习页导航、组件及数据存储，不改变其它业务逻辑。
- 为「速算训练」建立入口与空态，写失败测试 → 最小实现 → 重构。

### Phase B — 纯函数题目引擎
- 建立题型、正确值、精度格式、选项间距、随机种子模型。
- 先写 property/边界测试：四选项唯一、正确项恰一、舍入与量级一致、可重复、答案位置不固定；再实现。

### Phase C — 答题和结果页
- 先覆盖答题锁定、单次计时、跳题、结束统计的失败测试；实现后重构。
- iPad 横/竖屏交互，不需要物理键盘。

### Phase D — 回归与验收
- 静态检查、相关 host/unit 测试与现有 frontend/e2e 测试（依 AGENTS.md 约束执行；不擅自编固件）。
- 验收人工例题：
  - `387 ÷ 31 ≈ 12.48`，四项 `12.3/12.4/12.5/12.6` → 唯一选 12.5；
  - `438 × 27 = 11826`，四项 `11600/11700/11800/11900` → 按百位四舍五入选 11800；
  - 大间距题能较早停止试商，小间距题必须往下一位算；
  - 混合模式随机的是选项间距，绝不展示预设有效数字提示。
- 最终 PR 在候选 HEAD 上运行对应 CI，通过后才建议合入。

## 6. 不做的事

- 不把练习做成“必须输入精确商/积”的口算器；
- 不为展示精度单独开一个用户必填开关；
- 不新增后端服务/数据库迁移/移动 App；
- 不在这次 Plan PR 中修改产品功能代码或部署设备。
