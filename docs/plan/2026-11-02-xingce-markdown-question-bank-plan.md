## 一、用户已经确定的产品约束

1. **Markdown 是真题内容的唯一正式可编辑来源**；一套试卷一个 `.md`，必要图片单独存储。SQLite 将来仅保存索引、题目关联和个人作答记录，不作为题干/材料正文的主存储。
2. 整理 **来源内全部年份的行测，不设年份下限或上限**：国考、各地省考、来源内存在的不同卷型及独立考试序列（例如广州、深圳）；排除申论、模考、预测题及明显不属于目标考试的文件。来源标题/逐题来源与文件元数据冲突时，列为待核，不擅自更改卷籍。年份是检索属性，不是纳入资格；新年份沿用同一导入规则，无需修改代码或 schema。允许用户显式指定可选年份筛选，但默认不筛年份；年份缺失或冲突进入待核，不能凭目录猜测后静默纳入正常卷池。
3. **保留题干、真实选项、参考答案、原始解析、模块、题型、已有考点、文段出处、共享材料、公式及实际引用图片**。有解析即忠实保留，不由 AI 摘写；解析可长可短。
4. 不在最终试卷 YAML 中写 `paper_id`、`source`、`source_url`；不输出原始 `qid`、`doubt`、`reasoning`、`fastest`、`mother` 等字段，不附加用户没有要求的推理链。原始来源与版本追溯保存在**本地导入记录和质量报告**，不是每卷的 Frontmatter。
5. **三种稳定身份缺一不可**：`paper_id`、`question_id`、`material_id` 均使用 **UUIDv7**，保存在独立 HTML 注释中；首次设备同步时自动生成并写回 Markdown，不要求电脑 Agent 提前生成；已有 ID 必须保留。
6. `Question 116` 是**该卷题号**，不是跨卷唯一 ID；`M1` 是**该卷材料局部引用名**，不是稳定材料 ID。两者在同步时均需解析并关联到各自 UUID。
7. 资料分析、言语篇章阅读、判断推理「一拖五/一拖多」共用同一套 `Material` 机制：**材料只保存一次，题目可引用一份或多份材料**。
8. **共用已有 Samba 进程、端口和账号，新增独立可读写 share**；不要复用现有 `hyz-cards` 的目录树，避免 Flashcard 递归扫描并试图按 `## Card` 解析。
9. 题库允许人工编辑，使用本地 Git 追踪修改；**Git 历史不能替代冲突检测或自动备份**，导入器不得静默覆盖手工修改、丢失 UUID 或破坏旧题序。

> 版权边界：去掉平台名前缀、`source` 字段或改变存储格式，不等于获得试卷、解析和图片的再分发许可。本次按用户明确要求将 `papers/` 与 `assets/` 纳入公开主仓库；这项提交不代表上游内容取得再分发许可，后续来源及授权情况仍需单独核实。

## 二、已确认的上游事实及不确定性

上游是「一份卷一个 Markdown + 图片」，按 `国考/<年份>/`、`省考/<地区>/<年份>/` 分类。其 `docs/SCHEMA.md` 定义题干、选项、逐题折叠答案解析及位于题组前方的共用材料。

原方案记录：截至上游 2026-10-30 公开覆盖报告，2016–2026 的**行测试卷文件共约 513 份**（各年数值求和；并非已经认证完整的 513 套官方原卷）。该数字仅是旧年份窗口的历史参考，本次 review 未重新核验上游；不能代表全年份数量。运行时以固定来源 commit 的实际清点和 `catalog/manifest.jsonl` 为准，不能把 513 或旧年份窗口写死。上游全库（含申论及其他年份）已确认的缺题干 280 题位、缺选项 6 题位、缺参考答案 7 题位，**不能直接当成本项目筛选后的缺失数量**。

抽样确认的两类题块：

- 采集版：`### 第 N 题`、`A. ...`、`<details><summary>...`、`**参考答案（粉笔题库参考内容）**`、`**解析**`、`**考点**`、`**来源**`。
- 整编版：`## 第 N 题 <sub>qid ... · 类别</sub>`、`- **A**. ...`、`**答案**：X`，解析标题可能为 `**官方解析**`。标题中的 qid 只用来辅助导入验证，不进入目标 Markdown。

已观察到：
- 2016 国考副省级、2025 浙江 A 类有模块题号范围表和大量逐题 `考点`。
- 2024 江苏 C 类缺统一模块范围表，但题目标题附有片段阅读、逻辑填空、增长、比重等类别；也有 `## 材料 1（第41—45题共用）`。
- 2026 国考副省级存在 `## 材料 1` 后接篇章阅读题组的布局。
- 2019 四川样本材料后接 86–90 等资料分析题组，且逐题 `来源` 显示「四川选调生」而文件标题写「420 联考四川卷」；**逐题来源不必然等于文件实际所属考试**。
- 文件中部分题目是缺题占位、答案缺失或题序待核。正确解析并不保证来源真实性或官方原卷认证。

**先全量审计来源内全部年份的题型、材料与考点覆盖率，再批量执行转换。**

### 与现有 SMB 的边界

目前电脑 `scripts/share-flashcards.sh` 配置单个 `hyz-cards` 共享，既有设备端 Flashcard 根目录是 `/mnt/hyz-cards`。**不能直接运行一次修改共享名的旧脚本当作“增加第二个共享”**：该脚本管理自己的 Samba 配置块，还会处理全局端口及服务重启。

后续设备接入阶段在同一个 `smbd` 配置中新增独立 `[hyz-question-bank]`，复用既有 TCP 端口/账号，允许读写，固定挂载至 `/mnt/hyz-question-bank`；保留 `hyz-cards` 原样，不让现有 Flashcard 扫描器接触真题文件。修改 Samba 配置时必须做备份、配置测试和双共享回归。

本轮已补共享/挂载脚本及主机测试，**不实际改主机 Samba 或设备挂载**。

> 以上题干、选项、答案是**格式示意**，不是声称对应真实试卷第116/117题。

身份规则：

| 名称 | Markdown 位置 | 用途 |
| --- | --- | --- |
| `paper_id` | `<!-- hyz-paper-id: UUIDv7 -->` | 全卷唯一身份、整卷进度 |
| `material_id` | 每个 `## Material Mx` 后的 `<!-- hyz-material-id: UUIDv7 -->` | 共享材料稳定身份 |
| `question_id` | 每个 `## Question N` 后的 `<!-- hyz-question-id: UUIDv7 -->` | 收藏、错题、作答、跨模式引用 |
| `Question N` | 题块标题 | 保留源卷内题号（在该卷内唯一） |
| `M1`/`M2` | 材料标题 | 只在本卷内有效的可读引用名 |
| `materials: [M1, M2]` | 单题元数据 | 将题目解析到同卷对应材料 ID（支持多份） |

约束：

1. 电脑端初次生成文件时**可以省略三种 UUID 注释**；板端首次同步自动分配合法 UUIDv7 并原位写回，不要将 `UUIDv7` 字符串当真实 ID 写入。
2. 校验 UUIDv7 版本、格式和唯一性。重复、非法、歧义或丢失已有标记时应报告并拒绝错误关联，不能默默重新分配替代旧 ID。
3. UUID 与题号/材料序号**解耦**：重命名、移动文件、重排题目和调整 `M1` 名称，不自动改变对应稳定 ID。
4. 材料仅存一份，同卷 `materials` 引用必须解析到且仅到指定材料。空数组 `materials: []` 表示无共享材料；不允许悬挂引用。材料自身不是一道题，不计答题数。
5. Markdown 可省略无意义的可选字段，但字段名及区块边界一致。保留原始 Markdown 中有意义的粗体、特殊字符、公式、表格、图片和 HTML；解析器不得仅凭分隔横线 `---` 切题。
6. `Question N` 的编号允许原卷缺号且不重新压缩；必须将缺题位单独记录。用户界面将来可同时显示「专项第3/10题」与「原卷第26题」。
7. 原始 `qid` 不写入正式文件，未来用户收藏和错题**只引用 `question_id`**，不依赖源仓库 qid。

## 五、共享材料：资料分析、篇章阅读、一拖多

三种场景统一为 `## Material M1` 与 `materials: [M1]`，**不能根据模块假设一组必有五题**。

| 场景 | 材料可能包含 | 练习时要求 |
| --- | --- | --- |
| 资料分析 | 统计文字、表格、图表、公式 | 抽到任何一题即可带出完整材料；连续题组仅展示一次 |
| 言语篇章阅读 | 完整文章、段落序号、标记位置、插入句 | 保留文章/段落原貌和题号关联 |
| 判断推理一拖五/一拖多 | 共同情境、逻辑约束、条件、图形 | 单题展示全部必要条件；整组模式按原顺序共用材料 |

材料映射优先级：

1. 读取源的明确材料范围，例如 `## 材料 1（第41—45题共用）`。
2. 读取题目中的明确「关联材料」标记及任何显式多材料引用。
3. 对仅有 `## 材料 N` 后接连续题目的格式，可在**可验证的题组边界**上解析连续引用（例如下一材料、明确章节结束、已知题组范围），并记录关联依据。
4. 范围不明或互相矛盾时，标 `material_link_unverified`，保留材料和题文并交人工复核；**不得只因为紧邻材料就无条件归入所有后续题目**。

转换时不得改变材料中引用的段落位置、标点编号、表格结构或图形。共用材料中的图片只存一份。材料内容被上游编辑但仍是同一材料时保留 `material_id`；新材料或不确定对应关系必须报告而非盲目继承 UUID。

## 六、脚本提取规则（不逐题调用 AI）

| 字段 | 首选来源 | 缺失处理 |
| --- | --- | --- |
| 试卷标题/考试/年份/地区/卷型 | 源 Frontmatter 与文件路径 | 不一致报告冲突 |
| 原卷题号 | `第 N 题` 标题 | 缺号/重复号报告 |
| `module` | 卷首「题型模块—题量—题号范围」表 | 由已核实类别映射；否则 `null` |
| `category` | 逐题类别、原有考点及显式题型 | 规则映射；否则 `null` |
| `topics` | `**考点**：...` | 原样拆成列表；否则 `[]` |
| `passage_source` | `【文段出处】...` | 原样保存；否则 `null` |
| 答案和解析 | `<details>` 中的答案、解析标签 | 无答案标缺失；无解析省略 `Explanation` |
| `materials` | 共用材料标题、显式题组、可核实边界 | 未核实写异常，不乱关联 |

注意：`topics` 可同时包含「成语填空」「关联关系-并列关系」等不同层次标签；不应按文本顺序武断判定第一个是题型、第二个是考点。将「成语填空→逻辑填空」等**确定性分类映射表**独立维护，同时记录每项是原始值还是规则衍生值；不确定就保留原始标签，避免污染筛选。

`【文段出处】` 主要是文章溯源而不是试卷 `source_url`。逐题 `**来源**` 可辅助发现错卷，但不能用于自动改写卷别。来源信息若仍在原始解析的正文中，保持其原貌；另行抽取到本地质量/溯源清单，不在卷级 YAML 添加来源字段。

本轮不调用 AI 补缺失题型或考点；先统计覆盖率，后续由用户决定是否仅对缺失项进行 AI 标注。

## 七、数据质量、安全和可作答状态

以下状态明确区分，且不能互相代替：

- `ready`：题干、必需选项、答案、必需材料和图片齐全，并且没有已知错误；仅表示**可作答**，不代表官方验真。
- `missing_stem`、`missing_options`、`missing_answer`、`missing_material`、`missing_image`：已知缺损。
- `answer_unverified`、`order_unverified`、`material_link_unverified`、`source_conflict`：有可读内容但证据不充分。
- `parse_failed`：格式未识别，保留源文件并阻止丢题后发布。

缺题占位要保留在原题位与报告中，不编造真实题面/选项/答案，不把它们计入可作答池；若一题同时有多项问题，报告须允许多标签，统计去重口径要明确。**绝不能拿“机器检查无异常”宣称全部试卷官方完整。**

转换和设备同步应校验：
- 试卷数、声明题量、题块数量、题号唯一性与原题位保留；
- 选项字母/数量、答案与选项关系、多选题兼容；
- 答案解析归题准确、Markdown/HTML/LaTeX 未截断或串题；
- 题型/模块/考点覆盖率与有效性；
- 共享材料边界、无悬挂引用、多材料顺序；
- 图片路径可解析且文件能解码（包括 Markdown `![](...)` 和 HTML `<img>`）；
- UUIDv7 不重复，已有 ID 不丢失，源题序变更不引发旧收藏错绑；
- 逐题来源与卷级身份冲突；
- 来源版权/使用权限不明时不自动公开再分发。

图片/公式若原本是图片，保留原图，不强转不确定的 LaTeX。图片、原始解析及材料范围内的全部必要附件都应纳入引用闭包，不要错误地只保留题干图片。

## 八、UUID 首次同步、增量更新与冲突

**电脑端转换器**与**设备端首次同步器**负责不同事情：

- 电脑端转换器：生成规范内容、保留已有三类 UUID 注释、建立源文件与目标文件映射、比对内容指纹，产生可审查变更和异常。
- 设备端（下一阶段）：用户点击同步，先校验完整目录与已有 UUID；对**确实无 ID 的新试卷/新材料/新题目**生成 UUIDv7 并通过 SMB 安全写回；成功复核后更新本地索引。

设备端拟议安全流程：

1. 检查 SMB 已挂载且可写、目标是真实常规文件、路径不越过挂载根、文件大小在约束范围内。
2. 完整解析并预检 UUID、题号、材料引用、重复 ID 及重要缺损；对可修复的缺 ID 生成待写入计划。
3. 以同目录临时文件重写**仅必要注释**，复核文件内容和 UUID，尽可能保证单文件原子替换；CIFS 写入/rename 失败时保留失败报告，**不宣称跨文件原子事务**。
4. 再次扫描确认 UUID 和文件内容，才事务性更新本地索引；异常不能造成半批学习记录错绑。可重试与幂等恢复必须有测试。
5. 相同输入第二次同步不产生新 UUID、无意义 Markdown diff 或重复索引。SMB 读写仅是能力，不代表普通同步可任意改题文。

电脑端后续执行 `--update` 时，应依据既有 ID、之前保存的源/目标映射与题目/材料内容指纹做三方比较：

- 同一题内容修改且身份可核实时，**保留 question_id**。
- 题号变化或上下游重排时，不能只用数字 `N` 推断新旧题相同。
- 源变化与人工编辑同时发生时进入冲突报告，不静默覆盖用户版本。
- 不可确认匹配关系时暂停关联，保留旧文件/UUID 和对应学习记录，等待人工处理。
- 新题分配新 ID；已确认删除题目的历史学习记录保留为不可用/归档关联，不重新绑到其他题目。
- Git 不自动 `push`；不未经授权做破坏性的 reset/clean/覆盖。保留来源 commit、文件哈希、构建版本、人工修改状态与变更报告。

## 九、未来刷题和持久化接口（只定契约，不实施）

- **整卷刷题**：按卷 UUID 和原题序读取试卷，展示原卷题号与材料；缺题占位清晰提示，不计入可作答题。
- **模块/题型/考点专项**：通过 `module/category/topics` 索引跨卷查询；一次练习有独立 `display_index`（如「3/10」），原题号仍显示「某年某卷第26题」，不修改 Markdown 标题。
- **单题与整组练习**：抽到题目必须解析完整 `materials`，需要时支持按 `material_id` 将一拖多题成组抽取。不得将共用材料拆成彼此不一致的多个副本。
- **收藏/错题/作答历史**：以 `question_id` 为主键关联，纸卷/材料 ID 作外键；答题结果与原题文本隔离，避免源题更新删除私人历史。
- **答案保密**：前端提交前不得从刷题 API 或页面数据中泄漏 `Answer`/`Explanation`；与 Markdown 本地存有答案不矛盾，后端返回内容必须按答题阶段裁剪。
- **AI 出题**：未来可从所选真题、收藏真题、现有 Flashcards 或两者组合提供上下文，但生成的新题与真实试卷分开管理，不混入真题正文。

本轮**不修改** `/userdata/hyz-things/flashcards.db`、FSRS、VCNT、现有 AI 训练流程。

### Review 补充建议：套装、分类与练习契约（待确认）

现有「一卷一文件 + 稳定题目 ID + 共享材料」适合作为内容底座，但尚不足以完整表达套装和分考点刷题。此处将「套装」理解为有顺序的试卷合集或专题题单；以下仅预留契约，不把对应实现加入本轮 P0–P2。

1. **套装独立于原卷。** 后续新增 `collections/` 声明文件，区分「试卷合集」和「有序题单」；使用稳定 `collection_id`，按顺序引用 `paper_id` 或 `question_id`，不复制题文，也不以文件路径或题号充当身份。一题可以属于多个套装，移动套装不改变原卷归属；失效引用明确报告。设备分配 ID 前可整理原卷，正式套装引用须在 ID 写回后建立。模考或预测题未来若引入，应另定内容类型和来源规则，不因支持套装而自动混入真题池。
2. **原始标签与标准分类分离。** Markdown 保留原始 `module/category/topics`；独立可编辑、带版本的分类表定义稳定分类 ID、父子关系、别名及原始标签映射，索引保存标准分类关联。分类改名不改变分类 ID，一题可关联多个考点；未映射项保持待分类，不自动猜测。按父节点查询聚合子考点，同题命中多个考点时去重，统计不能重复计题。分类表也是受 Git 管理的来源文件，不能只存在于可重建索引中。
3. **专项抽题要有明确单位。** 区分单题模式和整组模式：单题模式带齐所需材料；整组模式维护明确的题组成员和原顺序，不能仅凭共享某个材料 ID 的连通关系推断所有题都属于一个题组。多个题组可共享材料，单题也可引用多材料。抽样时先确定单位，报告实际题量，避免目标 10 题实际抽成 10 组。
4. **练习实例固定成员，记录内容版本。** 开始练习时保存题目 ID 列表、展示顺序、模式、筛选条件及内容版本/哈希；恢复练习不重新执行动态筛选。正文仍由 Markdown 提供，历史作答记录引用内容版本；若需要准确重放旧题，须另定可读取的只读历史版本保留策略，不能仅存哈希便承诺重放。标准答案更正后保留原作答和原判分，重新判分应明确记录。
5. **质量状态必须能驱动筛选。** 第七节的逐题问题标签需有正式机器可读表示（例如题目 metadata 中的 `issues` 列表）和确定的 `ready` 推导规则，不能只写在可丢弃报告里。默认练习池要求题干、选项、答案、材料及附件通过校验，且不存在影响作答/判分的未核实项；来源冲突单独待核，未知分类不阻止整卷作答，但不进入对应专项。源内容、人工复核结论与本次扫描结果分别记录，明确合并规则；重建索引不能丢失人工标记。
6. **同步要检测编辑竞争。** UUID 写回前后核对读入版本/内容哈希，检测到人工编辑则停止覆盖并重试；并发同步要串行化。普通 CIFS rename 不能提供跨客户端比较后交换保证，实施时需选定编辑协作/锁定或冲突副本恢复方案，并保留被替换版本。挂载离线、扫描失败或目录只读不等于用户删除题目，不得据此归档整个题库。

**建议补充的后续验收**：同题加入两个套装仍共享收藏与历史；分类别名和父子节点查询正确去重；多材料题不造成题组无限合并；恢复练习成员及顺序不漂移；答案修订可追溯；无年份筛选能纳入旧窗口外试卷；同步与人工编辑冲突不丢内容。分类映射和质量状态的格式应在 P1 固化前评审，套装和练习实例实现仍留给后续阶段。
