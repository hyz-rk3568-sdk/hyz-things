# 资料分析：新题不复用、手动考点与独立找数生成

状态：用户确认实施（2026-10-22）。

## 目标及行为

- 综合训练「主动出题」每次均用最新 PC 仓库 hyz Skill/Flashcard，通过 Codex 生成 4 份×5 题。不从 `data_analysis_groups` 复用历史题组；同一任务的已备好试卷可恢复，只有再次主动请求才新生成。
- 原始官方统计公报参考资料可以继续缓存；旧材料、题目与作答记录持久保存，历史详情可回看。
- 在综合训练的自动薄弱点之外，提供可多选的「手动强化考点」（最多12项），**分类只使用 `flashcards/资料/错题/` 的直接子目录名**。优先实时读取 RK3568 挂载的卡片目录（挂载根可为 `flashcards/`、`资料/` 或仓库根）；挂载不可读取时回退已导入 SQLite 的 `deck_path`。选择保存在当前浏览器 localStorage。
- 手动选中考点会传入后端，校验属于当前错题文件夹分类后分配到四份材料的命题 Prompt；同时 Codex 会按 `flashcards/资料/错题/<分类>/cards.md` 或 `card.md` 找到该分类的真实错题。自动薄弱点也使用相同目录类别，以卡片数量、复习 lapse 与练习错误为排序依据；不依赖预置基础公式标签。
- 每份综合训练材料400–1000字、2–4自然段，围绕同一个统计大主题，按总体、分主体、指标/年份口径等关联小主题分段；四篇尽量大主题不同。找数训练已取消，不再生成独立定位材料。
- 找数训练每次主动请求都会调用 Codex 按其独立结构 Schema 生成模拟材料、5道定位题；不可复用旧综合题组或定位题集。原有按字节位置点击、记录正确率、单题用时及刷新恢复不变。
- 前端删去无意义的「合格材料组」数字、旧「已通过」文案、找数的旧材料复练开关，进度改为「已生成」。
- 综合训练**暂不生成综合分析多陈述判断题**（如“下列说法正确/错误的是”“能够从材料中推出的是”）。`综合分析与审题` 是可用错题分类，仅供 Codex 学习审题/年份/口径方法，并转换为单一计算或比较题；禁止规则优先于手动勾选与自动推荐。保持 Codex 内容自检，不恢复 Rust 数学或语义验题器。
- 审题、计算、干扰项与答案逻辑继续归 Codex 自行负责；Rust 不复算数学或跨年统计数据。找数必须保留将模型输出锚点转化为可靠点击区间的技术处理。

## 主要边界

- `data_analysis_groups` 仍保存训练生成的材料，用于历史结构和兼容旧记录，但不会用于新的综合出题或找数出题；这不是「新训练生成缓存」。
- 手动考点优先从 RK3568 实时挂载的 Flashcard 目录读取文件夹名，目录无法读取时使用上次导入 SQLite 的类别作为回退。Codex 使用 PC 工作树的最新 Skill/Flashcard；两端挂载或同步不同步时，选择面板可能暂时与 PC 不一致。
- Codex 的 comprehensive/five-choice 与 locating/text-anchor 两套 outputSchema 分离；后台只解析各自所需的展示/定位字段。
- 保留原本权限、会话/CSRF 与 Codex 最大并发限制。
- AI 内容是否真实分段、题目是否充分覆盖全部选中考点取决于 Codex 执行；此方案不引入 Rust 文本或数学验题器。

## 验证

- Rust native：历史试卷可恢复，且不靠生成缓存产生新题；Codex Schema 彼此独立。
- Playwright：入口存在、手动选择确实通过 POST JSON 传递；模拟材料中的换行在 iPad 上保留；找数5题流程和刷新后继续。
- CI 运行格式检查、单元测试、Web 构建与 E2E 后方可合并；真实 App Server 读取 PC Skill/Flashcard 的表现部署后冒烟验证。
