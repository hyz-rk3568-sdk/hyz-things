## 一、目标、范围与前置状态

本轮完成 **同步题库 → 选择原卷 → 选择整卷或该卷的一个完整模块 → 答题 → 交卷判分 → 查看解析 → 真题错题/收藏复练 → 历史记录** 的完整闭环。整卷、原卷模块、错题、收藏四种练习模式共用一套答题引擎和 UI，不重复实现四套系统。

本轮实现：

- [ ] 修复 Question Bank 409 同步冲突，实机完成全量索引和重复同步验证。
- [ ] 在「学习中心 → 专项训练」接入「真题训练」。
- [ ] 选择原始试卷，支持**整卷训练或该卷某一个完整模块训练**，计时、暂停、恢复和交卷。
- [ ] 从所选原卷实际模块中选择，展示真实题量；题目严格按原始题号顺序，**不跨卷随机抽题、不设置固定 20 题数量**。
- [ ] 支持独立题目及共用材料、一拖多、多材料引用。
- [ ] 复用现有 iPad 沉浸式训练、60:40 双栏、滚动、Markdown/图片/公式及 Apple Pencil 草稿能力。
- [ ] 提交后服务端判分，提供成绩、逐题答案、原始解析和 `topics` 复盘。
- [ ] 实现**仅属于 Question Bank 真题**的收藏、错题、错题复练、收藏题训练。
- [ ] 保存未完成练习、历史作答及内容版本关联。

**本轮明确不实现：**

- **跨试卷随机模块训练、跨卷随机抽题、自由组卷**；~~`category` 二级题型训练~~已在后续的全库模块刷题中补充，`topics` 三级考点训练仍属本阶段范围之外。
- 全库分类归一化、`category` 批量补齐和六大模块批量修复（另行实施）；但原卷模块训练必须对现有**确定性 `module` 别名/错层级**做最小兼容，避免漏题。
- 自定义题单、多卷合集、AI 相似题。
- 与 Flashcard 错题卡、FSRS、VCNT 或 AI 生成题的错题/收藏合并。

「套卷训练」在本轮明确指**选择一份原始试卷，做整卷或该卷一个完整模块**，不是跨卷组卷。原卷模块练习保留原始题号与题目顺序，题量为这份卷该模块的实际数量，不随机补题。年份不设置 2016–2026 等固定界限，列表来自 Question Bank **实际收录的全部年份**。正常训练只选择 `role: primary` 试卷，`role: evidence` 不独立进入正式练习池。

## 二、技术边界与统一设计

1. **题文来源：** `hyz-paper/v1` Markdown 仍是题干、选项、答案、解析、共用材料和 `topics` 的唯一正文来源；SQLite 保存索引、练习实例及个人学习状态，不复制整卷正文作为主存储。
2. **稳定身份：** 继续使用已有 `paper_id`、`question_id`、`material_id` UUIDv7；所有收藏、错题、作答和历史使用 `question_id` 关联，不按题号或文件路径绑定。
3. **四种训练模式复用：** 统一 `QuestionBankPractice`（命名可按仓库惯例调整）。选题来源分别为整份原卷、指定原卷的一个完整模块、待复练真题和已收藏真题。计时、导航、提交、判分、材料、草稿和复盘完全共用；不实现跨卷随机模块抽题引擎。
4. **答案安全：** 普通整卷加载与作答前的任何响应不得包含 `Answer`、`Explanation` 或可能泄露正确答案的 `Notes`。答案只由服务端读取与判分；完成提交且通过授权检查后，才能通过专门复盘接口下发。
5. **数据隔离：** 所有真题学习状态位于 Question Bank 自己的 SQLite 表与 API；不得修改 `flashcards.db`、FSRS、VCNT、已有 AI 训练结果。
6. **权限边界：** 复用现有管理员 Session；敏感读取受授权保护，创建/保存/交卷/收藏等写请求使用同源 Origin 与 CSRF 校验、结构化参数和请求体大小上限。
7. **内容质量：** 有缺失题干、选项、答案、材料或待核标记的题目不能假装为正常可判分题；应在入卷前明确策略并在 UI 告知。默认以可安全作答、可判分题目为练习候选，整卷若含不合格题位须明确列示及处理，不能静默改变原始题号。
8. **原始考点：** `topics` 原样保留；第一版只在交卷解析、错题复盘及历史复盘展示，不作为本轮抽题条件。
9. **原卷模块练习契约：** 指定 `paper_id` 与一级 `module`，选出该原卷属于该模块的**全部题目**，保持原始题号、原卷顺序、共用材料引用和真实题量；不依赖 `category` 是否存在。
10. **模块归属校验：** 政治理论和常识判断继续作为两个独立的一级模块；对 `module: 图形推理` 等明确的错层级使用确定性、只读别名归位到 `判断推理`，不因此改写题库 Markdown。模块未知或归属有冲突时，显示未归类题量并提示，不猜测、不中途丢题。

## 三、P0：修复 Question Bank 同步冲突与实机索引

**优先级：最高；通过实机验收后才认定题库可支撑练习。**

### 当前问题与根因验证

现有 `QuestionBankApplication::sync()` 的 `Semaphore` 随调用 Future 释放；实际大批量文件扫描经 `spawn_blocking` 运行。HTTP 断开、页面刷新或请求取消后，blocking worker 可能继续扫描，造成下一请求与尚未退出的任务重叠。前端 `busy` 只是页面本地状态，刷新后不能代表设备的真实同步状态。

但 **HTTP 409 不能一概归因于重复点击**：`question_bank_busy` 和 `question_bank_conflict` 是不同错误。现场记录为 `question_bank_conflict`，实现前应明确记录冲突触发阶段和准确原因，补充能复现的测试。

### 实施任务

- [ ] 同步改为**后端持有的独立任务**；任务持有互斥权直到扫描、UUID 写回、索引事务提交/回滚彻底结束，不受 HTTP 请求断开影响。
- [ ] 重复点击、并发请求或页面刷新不能启动第二个扫描任务；对相同运行中任务返回其状态，不触发重复写入。
- [ ] 后端记录 `idle → scanning → validating → writing_ids → indexing → completed/failed`（可调整实际阶段），含任务 ID、开始时间、进度、结果与脱敏错误码。
- [ ] 增加状态查询，例如 `GET /api/v1/question-bank/sync/status`；将原同步 POST 改为短请求启动任务并返回任务 ID/状态（可采用 HTTP 202）。页面进入时先查询状态，再启用/禁用按钮；页面刷新后可继续追踪。
- [ ] 对 `question_bank_conflict` 加入分阶段诊断：重复/缺失身份、写回前后内容哈希变化、文件冲突、已有索引身份不一致等，错误信息不泄露敏感路径或凭据。
- [ ] 保留 CIFS 写回前的文件版本复核、备份、临时文件原子替换和冲突停止策略；扫描失败不覆盖旧索引。
- [ ] `papers/identities` 及后续练习/收藏/错题表保持事务一致；增量同步不清空个人数据。挂载离线不代表试卷被删除。
- [ ] 补齐/验收设备开机挂载与异常恢复；不影响已有 `hyz-cards` 共享及 Flashcard。
- [ ] 如有索引更新与大量 Markdown 同步写入，确保失败后可重试且 UUID 不重复分配。

### 验收门槛

- [ ] 实机 739 份当前候选 Markdown 全量扫描、索引完成，并报告与源数量一致的索引计数（正常练习列表只显示 `primary`）。
- [ ] 有效 UUID 无重复、无非预期改动；重复同步时 `generated_ids = 0`。
- [ ] 浏览器刷新、网络断开、连续点击、两客户端并发操作均不会启动重叠扫描。
- [ ] 共享临时不可用、人工并发改文件、处理中断能够明确报错并安全恢复。
- [ ] 已有练习、收藏、错题、历史关联不随重复同步丢失。
- [ ] 设备重启后挂载、只读题目列表和素材访问可恢复。
- [ ] 不将目前的现场 409 诊断写成已修复事实，直到实机再次完成端到端验收。

## 四、P1：统一练习模型、内部答案与服务端判分

**目标：将只读 Question Bank 扩展为安全、可恢复、可判分的练习服务。**

### 数据模型

在 `question-bank.db` 保留现有 `papers`、`identities`，逐步增加：

| 逻辑表 | 最小职责 |
| --- | --- |
| `questions` | `question_id`、`paper_id`、原始题号、内容哈希/版本、有效性及必要索引 |
| `practice_sessions` | `session_id`、模式 `paper/paper_module/wrong/favorite`、状态、起止时间、计时、来源 `paper_id` 及可选 `module` |
| `practice_items` | 固定 `question_id`、原卷题号、显示顺序、对应源版本、作答状态、选项与草稿关联键；原卷模块练习快照全部成员 |
| `practice_attempts` | 历次逐题真实答案、判分结果、提交版本及时间 |
| `question_progress` | 逐题当前错题复练状态及汇总 |
| `favorites` | 每个 `question_id` 的真题收藏状态 |

具体表名与范式按现有仓库 SQL 风格确定，需支持幂等迁移。不要将个人学习状态混入可重建的题库扫描索引；重建 `questions` 不得删除 `practice_*` / `favorites` / `question_progress`。

### 核心业务

- [ ] 服务端内部解析 `Answer` / `Explanation`，与浏览器安全 `QuestionView` 分离；普通题面接口保持无答案。
- [ ] 创建练习时，固定题目 ID、顺序、试卷来源、显示序号及源文件内容哈希；恢复时不得根据当前筛选条件重新选题。
- [ ] 整卷按原卷完整题序创建；`paper_module` 由服务端根据 `paper_id + module` 确定**这份原卷对应模块的全部题目**，保持原卷顺序，不随机、不从其他卷补题、不按固定题数截断，也不接受客户端任意题目列表冒充模块练习。
- [ ] 服务端提供每卷实际可选模块及准确题量；对 `category: null` 但模块明确的题正常归类；明确错层级做最小只读映射，未知/冲突归属明确报告，不能静默漏题。
- [ ] 支持单选与源格式明确允许的多选，依照实际合法选项集合（而不是硬编码 A–D）校验提交。
- [ ] 按照服务端正确答案判分：正确、错误、未答、不可判分互相区分；已知缺损/未核实答案不可混进正确率分母。
- [ ] 作答按题持久化；刷新页面、退出再进入时能继续同一练习。
- [ ] 交卷必须幂等，防止重复提交、重复统计或并发保存修改已完成成绩。
- [ ] 用户访问练习实例或历史必须经过既有管理员身份授权。
- [ ] 内容更新后保留原作答与原判分结果；如果没有旧版本正文可用，历史复盘要明确提示内容已更新，不能显示新版题文冒充旧版。

### 建议 API（最终命名以现有路由风格为准）

```text
GET  /api/v1/question-bank/papers/{paper_id}/modules
POST /api/v1/question-bank/practice/sessions
GET  /api/v1/question-bank/practice/sessions/{id}
PUT  /api/v1/question-bank/practice/sessions/{id}/answers/{question_id}
POST /api/v1/question-bank/practice/sessions/{id}/submit
GET  /api/v1/question-bank/practice/sessions/{id}/review
GET  /api/v1/question-bank/practice/history
```

作答前 API 不能携带标准答案及解析，提交后复盘 API 才能在授权、状态验证后返回必要内容。

### 验收

- [ ] 未交卷的普通查询、HTML、JSON 与缓存均不泄漏答案/解析。
- [ ] 正确/错误/未答/不可判分及多选判分准确。
- [ ] 作答持久化、恢复顺序稳定。
- [ ] 原卷模块练习成员、实际题量及原始顺序与所选试卷完全一致；不跨卷随机抽取。
- [ ] 同一 session 重复交卷只生成一份最终成绩。
- [ ] 错题/收藏/历史与 Flashcard 系统物理及逻辑隔离。

### 统一答题 UI

复用以下现成组件/机制：

- `TrainingSplitWorkspace`：已有 60:40 两栏与竖屏上下堆叠布局。
- `MaterialScrollButton`：材料和题目区域独立滚动。
- `InkOverlay` / 已有草稿组件与工具栏：Apple Pencil 及触控草稿。
- `study_markdown.rs`：Markdown、受保护图片、公式渲染。
- 现有沉浸式训练的计时、暂停、导航、交卷提示、结果/回放交互模式。

**复用底层布局，不直接复制 `comprehensive.rs` 的 AI 出题业务模型。** 新增以 Question Bank ID 与 session 为核心的 `QuestionBankPractice`。

### 材料布局规则

- **有共用材料**：左侧 60% 显示共享材料，右侧 40% 显示当前题目及可选选项。两侧独立滚动。
- 同一材料组切换题目，不重复加载材料，也不重置其滚动位置；更换材料时才切换内容。
- 支持一拖二、一拖三、一拖五等实际题数，**不假定一个材料永远对应 5 题**；一题可以引用多份材料。
- 多题共享材料 ID 不必然代表一个固定题组；用于显示的关联来自实际 `materials` 引用，未来抽题组需另定成员契约。
- **无共用材料**：单栏展示题干与选项，不留下空白材料栏。
- 图片、表格、公式、长文本按现有安全 Markdown 渲染，滚动与 Apple Pencil 不互相干扰。

### 作答交互

- [ ] 用户选择/修改答案、跳过、使用题号导航、返回上一题/下一题。
- [ ] 单选、多选依据源题规则呈现，选项数不得固定为四。
- [ ] 支持计时、暂停、退出和继续；未答完交卷需要确认。
- [ ] 草稿按 `session_id + question_id` 区分，避免串题，保留已有草稿交互习惯。
- [ ] 真题作答和已有 AI 训练使用同一套学习计时管理机制，不产生重复计时。

### 验收

- [ ] 真实整卷从选卷到最后一题可以完成，不只验证假数据。
- [ ] 真正单卷模块练习能一次完整做到本卷该模块所有题目，原题号/顺序/题量一致；政治理论与常识判断分别显示，已知错层级归位不漏题。
- [ ] 有/无材料题都正确呈现，长材料滚动位置稳定。

## 六、P3：交卷、成绩、答案解析和 topics 复盘

### 交卷

1. 统计未答题数并提示用户确认。
2. 服务端锁定本次练习并执行幂等判分。
3. 记录成绩、有效判分题数、用时、逐题作答及源版本。
4. 进入成绩页；仅此后开放该练习的答案和解析复盘。

### 成绩页

显示试卷名称、总题数、有效判分题数、正确/错误/未答/不可判分题数、正确率与实际作答用时。正确率分母仅包含有效判分题，避免已知缺损题影响成绩。

### 解析复盘页

复用答题时的材料/题目布局，将右侧切换为复盘内容：

- 原题、选项与共用材料。
- 你的答案、正确答案、正确/错误/未答/不可判分状态。
- 正确选项和错选的不同标记。
- 原始 `module`、`category`（若存在），**完整展示原始 `topics` 详细考点**。
- Markdown 中的原始 `Explanation`，不存在时显示「暂无解析」。
- 收藏/取消收藏、上一题/下一题、返回成绩与历史。

本轮 **不依赖 `category` 是否已补齐**；`topics` 直接展示，不做三级筛选。

### 验收

- [ ] 成绩与逐题判分一致，无法判分的题有清晰提示。
- [ ] 交卷前不泄漏答案，交卷后授权访问复盘。
- [ ] 原始解析、图片、数学公式、详细考点展示正确。
- [ ] 旧成绩不被再次同步或更新答案静默改判。
- [ ] 解析为空时有明确占位，不虚构讲解。

## 七、P4：仅针对 Question Bank 的收藏、错题与复练

### 错题状态

- 首次判错 → 加入「待复练」。
- 判对 → 不新增待复练错题。
- 未答与不可判分 → 分别记录，默认不算错题。
- 错题复练答对 → 更新当前状态为「已掌握」，可从「待复练」移出。
- **历史错误尝试始终保留**，即使后来答对也不能删除旧错误记录。
- 错题筛选基于 `question_id`，不复制 Markdown，不因题号/路径变化而错绑。

### 收藏

- 作答时、查看解析时可以收藏或取消收藏。
- 同一题可以同时「收藏」和「待复练」。
- 取消收藏只改变收藏状态，不删除练习历史。
- 收藏仍是 Question Bank 专用，不与 Flashcard 收藏混合。

### 复练模式

- 「错题训练」从当前待复练题中取题创建固定 session。
- 「收藏训练」从当前收藏题中取题创建固定 session。
- 使用与整卷训练**完全相同**的题面、共用材料、草稿、计时、交卷、判分和复盘组件。
- 不提供跨卷随机抽题；错题/收藏默认按来源试卷、原始题号稳定排序。创建后成员和顺序固定，不得因列表变化导致 session 题目漂移。
- 即使跨卷取题，也要携带每题实际引用的共用材料与原卷来源。
- 收藏练习的交卷不会自动取消收藏。

### 验收

- [ ] 错题自动加入复练，复练答对改变当前状态但不删历史。
- [ ] 收藏、取消收藏正确且幂等。
- [ ] 重复同步、题目分类元数据更改后，状态仍绑定相同 `question_id`。
- [ ] 错题、收藏的跨卷材料完整。
- [ ] `flashcards.db`、FSRS、VCNT、现有 Flashcard 错题复练及 AI 训练结果不变。

## 十、2026-11-03 增补：全库模块 / category 专项刷题

> **需求变更：** 本节替代前文“本轮不做跨卷模块训练”的旧限制。原卷模块练习仍然只选单份试卷内的完整模块，不截题、不抽样；新「模块刷题」是另一种模式。自由组卷、纯随机跨卷抽题仍不做。
