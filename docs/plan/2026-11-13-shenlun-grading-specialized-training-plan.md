## 1. 已确认的产品决策

在 `学习中心 → 专项训练` 中增加与“资料分析 / 判断推理 / 数量关系”等并列的 **「申论批改」** 标签。使用既有国考、湖南省考申论真题，提供选题、材料阅读、作答、手写图片转写校对、AI 批改、按需查看参考答案和个性化优化稿、可选二稿修改、历史复盘；**练习诊断参考分**，不声称官方阅卷分。

**唯一申论 Skill 目录**：`.agents/skills/hyz-shenlun/`，一个 `SKILL.md` 入口按需读取小题、大作文及评分/反馈规则。仅参考 [coffe-d/Shenlun.skill](https://github.com/coffe-d/Shenlun.skill) 中必要的 MIT 授权内容；**不**搬运其 router、OCR、题库、命题预测、错题存储、导出器、双教师范文或全量讲义，不执行第三方脚本。具体采用的上游 commit、版权声明、删改内容及许可审计在实施提交中明确；第三方教师讲义和参考答案不因 Skill 的 MIT 许可证而自动获得再分发权。

**图片策略**：Codex **先直接看原图**，忠实转写，不擅自改错字/润色。遇到辨认不确定、混合印刷/手写、多栏阅读顺序等，再调用现有 `hyz-image-ocr` / PaddleOCR 作辅助交叉核验。**OCR 不能凌驾原图，任何识别冲突都展示待确认；用户确认/修正转写稿后才正式判分**。纯文字输入不经过 OCR。图片清晰也需有一次明确“确认转写并提交”动作，不以生成文本无误为假设。

**判分策略**：Skill 依据题干、完整相关给定材料、已有参考答案（若存在），独立建立本题点池/评分维度；有参考答案先用其作为候选，再回材料核验，不能把机构参考答案视为唯一标准。小题按语义采分、关键限定、任务要求、表述/条理；大作文按立意、观点关系、结构、论证和表达等维度定档。证据可核查、允许部分命中；**不**照搬固定 40%/80% 阈值、词面必须一致、机械保底或未验证的官方扣分公式。Rust 验证确定性约束并计算最终建议分，AI 不自由填写总分。无法确认分值、题目/材料不全或识别含关键歧义时只给诊断或明确待确认，不编造精准得分。

## 3. 用户流程与交互验收

1. **入口与选题**：`专项训练 → 申论批改`。按国考/湖南、年份、卷型、题型（归纳概括、综合分析、提出对策、公文写作、大作文、其他）筛选；点击整套卷或某题进入，前端展示材料、题干、题目分值、字数要求。未给分值的题显示“分值待确认”，不默认 10/40 分。历史题型 `other` 不凭题号臆断，允许 AI 建议分类但必须给出可追溯的依据，默认保留原分类。
2. **作答工作区**：使用 `TrainingSplitWorkspace` 的材料（左）/题干与答题（右），可拖动/独立滚动；答题卡、上一题/下一题、暂停、计时、沉浸式与窄屏行为沿用共享组件。支持文字长答、自动暂存、刷新恢复；保存输入与正式交卷分开。答案为空不能发起评分。
3. **图片转写**：支持现有 JPG/PNG 临时受控上传；调用 Codex 视觉一次转写所选页，返回页序与不确定字区段，用户在原图对照旁检查并修改。必要时再调 PaddleOCR 获取 `blocks` 佐证；禁止凭 OCR 猜测、自动补写答句或因原图模糊扣作文分。多页顺序需要明确并验证；现有附件数量/大小上限不足以覆盖多页时分批上传，不能偷偷放宽设备/PC 安全限制。用户确认后保存**转写文本及校对版本**；原始临时图过期后历史仍可看已确认答案，历史中不承诺恢复原图。
4. **提交批改**：用户明确点击“AI 批改”；服务端冻结 `attempt_id + 题目版本 + 校对文本版本`，执行 `hyz-shenlun`。当前答案批改完成前不展示来源参考答案或隐含采分点。首答后可查看原始参考答案（注明来源）与 AI 建议分。
5. **结果页**：顶部显示“练习参考分 X/Y”及可选建议区间/置信度，逐点命中/部分/遗漏、引用用户原句、对应材料证据与可执行修改建议；大作文按段落与维度分析。可切换“原稿 / 批注 / 参考答案”，高亮必须按原文本范围标注且字符索引可验证；证据找不到时降级为说明文字，不伪造高亮。
6. **二稿与历史（可选）**：不强制写二稿，首稿批改后可直接查看答案；若用户选择再练，在原答案上创建新修订（不覆盖初稿），重新批改后比较采分覆盖、结构与参考分变化。历史保存每稿、批改请求状态、所用 `skill_version/rubric_version/model`、时间、题目版本；重做与重新评分是不同操作，避免无意重复耗额度。AI 不可用或停止后，已保存草稿仍可编辑和恢复。
7. **参考答案与优化版**：首稿批改完成后默认折叠答案区域；已入库的来源参考答案可直接查看、注明来源且不额外调用模型。用户单独点击「AI 独立参考答案」才生成与学生作答无关的新答案，单独点击「我的答案优化版」才根据选定提交稿和其批改报告给出改进稿及改写理由。大作文优先逐段优化，完整范文需明确点击才生成；不自动双份生成。
8. **学习统计**：`shenlun` 的有效学习时间按既有心跳统计；“今日做题数”只按**本人确认提交的非空作答**记一次，纯 OCR 尝试、重试评分和二稿不重复刷计数。大作文与小题明细可后续扩展，第一版不与行测错题状态混合。

### 3.1 参考答案、个性化优化与二稿产品规则（用户已确认）

**三种答案要清楚区分，绝不统称“官方标准答案”：**

| 类别 | 输入/用途 | 生成时机与成本 |
| --- | --- | --- |
| **来源参考答案** | 直接读取当前题目已存储的 `reference_answer`，注明来源；机构答案可能不是官方采分点 | 首稿批改完成后可以直接看，**不需要 Codex 调用** |
| **AI 独立参考答案** | 由 Skill **只读取题干、对应材料、可用来源答案、题目要求**，独立组织完整可写的参考答案；**不得读取学生答案、漏点分析或批改分数**，以免被学生原稿污染 | 首稿批改完成后，用户手动点击生成；同题、同来源/Skill 版本缓存，默认不生成 |
| **我的答案优化版** | 由 Skill 使用**用户指定的已提交答卷修订版本**和对应批改报告，保留有效观点、补充漏点、优化结构/语言；逐项列出“原句→改写→理由” | 首稿批改完成后，用户手动点击生成；每个修订版本独立缓存、可重复查看，默认不生成 |

**大作文**默认给逐段诊断、分论点改善和可执行的部分改写；完整范文只在用户主动点击「生成完整范文」后生成，不能每次判分都自动输出千字作文。若用户要求完整范文，必须对照题干、字数、文体和材料核查，不可编造政策、案例或材料外数据。小题独立答案必须满足字数要求与文种要求，禁止为了“满分答案”虚构官方得分承诺。

**练习闭环**：独立作答 → AI 批改 → 看失分依据 → **可选择**修改二稿，也可直接看来源答案/AI 答案/个性化优化版。查看答案**不以二稿为前置条件**。一稿、二稿分别留档；已经看过参考答案再修改时，记录“参考后修改”，避免在统计里把分数上涨解释为完全独立的能力提升。重做（产生新学生答案）、重新批改（同稿再评）、生成参考答案、生成优化稿是四种不同操作，不能共用同一任务 ID/状态。

**评分与答案生成严格隔离**：申论评分点池独立于学生答案生成，不能让“我的答案优化版”回流作为评分点，也不能因为 AI 独立答案不同而重写已经完成的评分报告。所有独立生成任务都在**首稿正式提交且批改完成之后**解锁；服务端守门而非仅前端隐藏。支持单独停止、失败重试、幂等、流式状态，生成失败不删除草稿/成绩。原题或 Skill 更新时按版本失效/重建缓存，不串题、不串稿、不重放上次生成内容。

**页面呈现**：批改结果与“参考答案”区域分开；区域默认折叠，有「来源参考答案」「AI 独立参考答案」「我的答案优化版」三个明确入口，大作文另有按需「生成完整范文」。每种生成稿显示“AI 生成／非官方”、来源/所基于稿件、字数、生成状态与版本。未展开不额外调用模型；选项卡仅负责查看已存在结果，不触发隐藏的重复评分。

交互原则：本次无“公众号资料库/热点预测/押题”“名师双版本参考答案”“专项 PDF 导入”“手写实时笔迹识别编辑器”。Apple Pencil 可在现有草稿层书写，但**草稿 Canvas 不自动当作持久申论正文**；本轮正式手写提交走拍照上传；如实现草稿导出需另行验收像素比例、页序和隐私边界。

## 4. 唯一 Skill 的建议目录

```text
.agents/skills/
├── hyz-image-ocr/             # 已有，继续复用
└── hyz-shenlun/               # 本 Plan 唯一新增的申论 Skill
    ├── SKILL.md               # 唯一入口：判型、选择参考文件、执行顺序、安全边界
    └── references/
        ├── xiaoti.md          # 概括/分析/对策/公文
        ├── dazuowen.md        # 立意/结构/论证/档位
        ├── scoring.md         # 证据约束、部分命中、评分一致性、失败/降级
        └── feedback.md        # 原句引用、修改建议、二稿对照
```

- Skill 是模型执行规则、题型选择和反馈规范；**数据库状态、授权、请求幂等、分数算术、历史与上传边界属于 Rust 服务**。Skill 不直接写题库/数据库、不开关服务、不任意访问磁盘，不使用第三方 router/shell 脚本。
- 优先读取当前题干/关联材料/参考答案；`question_type=other` 时依题干慎重推断；有矛盾时报告“不确定”。`SKILL.md` 不一次加载全部名师库。
- 对本题生成**候选评分点池/评分维度**，点池由材料和题干核验、与参考答案对比、禁止读取考生答案来决定点池。缓存键 = `question_id + source_fingerprint + skill_version + rubric_schema_version`；基于已缓存同版评分点批改不同考生/二稿，避免随答案改变评分标准。题目文本、材料或 Skill 版本变更时新建版本，不回写旧报告；点池异常可人工清除/重建但历史保留原版记录。
- 不强制“标题必须 X 字”“必须总括句”“出现指定词才给分”“覆盖率超过阈值保底”。申论语义等价可以给分；材料外胡编不能靠表述好获得采分点。
- 同一个 Skill 兼顾判分与**按需答案生成**，但不同意图明确隔离：独立参考答案不得接收学生作答及批改报告；个性化优化稿只接收用户选定稿和对应反馈；大作文完整范文须用户显式触发。方法文件可按需加载，**不增加其他申论 Skill**。
- 输出应用层**严格 JSON 契约**（由 Rust 验证）而不是让前端解析自然语言 Markdown；聊天式改进建议仍可从结构化结果渲染。上传图片中的指令、Markdown 或材料均视为不可信数据，不执行。

## 5. 推荐的技术边界（在一个 PR 内实现）

### 5.1 数据：不破坏原有客观题模型

在既有 `question-bank.db` 下新增独立 `shenlun_attempts`、`shenlun_attempt_revisions`、`shenlun_grade_runs`、`shenlun_grade_items`、`shenlun_generated_answers` 或等效归一化表；严格不要将申论长文本塞进 `practice_items.answer` (A–Z 数组)，也不要把主观分数映射为 `correct/wrong`。每份草稿与提交稿都关联：`question_id/paper_id`、`source_fingerprint`、`revision`、已确认文本、来源类型（typed/vision-confirmed）、时间、`status`；评分版本及输出另外持久化；生成稿另外保存种类、题目版本、可选作答修订版本（独立 AI 答案必须为空）、Skill/模型版本、幂等请求 ID、生成状态和缓存键。使用新的 additive SQLite migration，不修改既有已执行迁移；备份与新旧库初始化测试，不删库重建。

只允许 `subject=shenlun` + `answer_type=subjective` 进入新业务；普通行测与 `kind=drill` 专项合集仍使用原有过滤与表。`reference_answer/explanation` 只在**服务端评分上下文**读取，未正式交卷/批改的客户端 DTO 不返回，不写入预提交 API。

### 5.2 服务与 API：独立应用用例，复用基础设施

建议在 `src/application/question_bank/shenlun.rs` 增加题目查询、答卷草稿、转写确认、批改任务、历史与版本检查；`src/adapters/outbound/shenlun_grading.rs` 通过已有 Codex App Server 执行（共享传输组件、请求 ID、SSE 事件与临时附件接收端）。`src/adapters/inbound/http/question_bank.rs` 或拆分 `shenlun.rs` 提供强类型路由。候选路由（实施前与现有 API 命名核对）：

- `GET /api/v1/question-bank/shenlun/papers`、`GET /.../questions/:id`：仅申论、无答案泄漏。
- `POST /api/v1/question-bank/shenlun/attempts`、`PUT /.../attempts/:id/draft`、`POST /.../attempts/:id/submit`、`GET /.../attempts/:id`：持久草稿、确认提交、历史。
- `POST /api/v1/question-bank/shenlun/transcriptions`、`POST /.../transcriptions/:id/confirm`：图片转写任务与用户确认；若可复用已有附件 ID、事件机制则复用，绝不把已确认正文变成一次性临时图片记录。
- `POST /api/v1/question-bank/shenlun/attempts/:id/grade`、`GET /.../grade/events`、`GET /.../grade`：异步批改，幂等请求 ID，SSE 进度/终态与断线恢复。
- **答案独立资源**（路由名称实施前与现有 API 统一）：已完成批改后的来源答案只读 API；用户按需发起 `independent-answer`（仅题目材料）、`rewrite`（按指定 attempt/revision）、`full-essay`（显式生成完整作文），并提供对应状态/流事件/缓存 GET。未完成首稿批改的用户通过直接 HTTP 请求也不可提前获取参考答案或生成内容；所有生成任务绑定题目/稿件版本并做 CSRF/权限校验。

不把“申论批改”请求当作现有 `question_bank_ai.rs` 的普通追问：现有初始 Prompt 固定“行测复盘助手”，会加载 `行测做题` 规则，且消息是按题而非按**答卷版本**组织。应共用底层 Codex 会话/流和附件传输组件、复用成熟的错误映射与事件模型，但申论应拥有明确的 `attempt_id + revision + grade_run_id` 身份，防止旧结果覆盖新稿。

### 5.3 评分执行契约

两个分离的意图：`transcribe`（输入图片，输出忠实文本/不确定片段/页序，不评分）→ `grade`（只用已确认文本评分，必要时图片可作为独立卷面反馈证据，但不得替代已确认文本）。一个有效 `grade` 运行包含：

1. 服务端按题目 UUID/版本取完整相关材料、题干、分值、原始参考答案；校验输入长度与来源，拒绝混题/缺资料，不依赖 AI 自己猜目录路径。
2. 准备或复用与作答无关的点池。对每点保留材料原句定位、候选权重/类型、可替代表述和不确定性；答案不必覆盖所有参考答案句子，但不得凭空出现采分点。
3. AI 对**已确认稿件**逐项输出 `coverage = full/partial/missing/unsupported`、用户原句 `quote + start/end`、材料证据 `material_id + quote`、依据、改进建议；大作文输出维度档位和段落证据。
4. Rust 按声明的评分项计算汇总、校验分值范围、重复点/交叉扣分、字符切片和引用位置。无可核验依据、JSON 契约错误、关键材料/OCR 不确定时不保存“成功得分”；允许保存不评分的诊断报告与错误回执。
5. 输出 `provisional=true`、题目满分、版本、建议分、扣/得分项、置信等级和一次性训练指导。老师教法只影响指导，不直接定义官方分数。
6. 同一次请求重试使用相同幂等键；停止、超时、远端结果不明、SSE 断连需有可恢复状态；历史报告不可被晚到的旧 run 改写。AI 批改是否启动由用户明确触发，不能浏览题目就自动消费额度。来源参考答案展示不消耗 AI，独立参考答案、个性化优化版、完整范文分别按需调用，不允许评分服务隐式生成第二份答案。

**分值缺失**：只给“未评分的练习诊断”，不要凭题型默认满分；若用户确实提供分值，标明用户输入并随提交快照存档。**OCR 未确认**：只能展示待校对转写，不得进入正式批改。**参考答案缺失**：允许材料独立点池，但降低置信度并保留该事实。

### 5.4 安全与运行条件

- 现有图片传输链路为浏览器 → RK 后端验证/转发 → PC 临时 `tmp/hyz-ai-uploads`，PaddleOCR 仅 PC 本机。禁止在 RK 上新增永久原图写盘，禁止任意 URL/路径/文件名/命令输入；落实登录、Origin、CSRF、尺寸/MIME/页数/超时/内存/配额检查。确认文本、评分报告存独立受限 SQLite；原图默认过期清除。
- **重要既存风险**：当前 Codex App Server 有 `danger-full-access` 运行配置。仅靠 Skill 中“不要写文件”不能形成安全隔离。实施前复核现有宿主机专用低权限账号、可访问目录、凭据与出站权限；如不能保证评分任务不接触高价值路径/凭据，先补 OS 级隔离或受限执行配置再开放新功能。第三方 Skill/试卷/图片均可能含提示注入，不执行外部仓库脚本。
- 保护用户私人作答，不上传到无关服务；任何使用云模型都需由现有 Codex 配置和用户的授权控制决定。日志不记原图 Base64、作答全文、参考答案和认证信息。
- 模型限额、OCR 不可用、部分页缺失、附件已过期时提供明确的可恢复状态，不丢失草稿，不假装已评分。
