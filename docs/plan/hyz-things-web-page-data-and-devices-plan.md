# hyz-things Web 页面数据、刷新与设备操作优化计划

## 状态

**待实施。**

创建日期：2026-09-14。

本文承接 [Web 前端结构与界面重构计划](hyz-things-web-frontend-refactor-plan.md)，定义下一轮门户优化的实施范围、用户行为和验收标准。本轮功能开发在一个独立分支中完成，通过一个 PR 交付。

当前用户确认的范围：

1. 设置按页面、模块独立加载、独立报错和重试。
2. 按当前页面请求数据，浏览器后台降频，回到前台立即刷新，统一表达数据更新时间。
3. 串联设备列表、详情、活动与策略修改，并精简相关页面。
4. 将导航位置同步到 URL，刷新、前进、后退和登录后保留目标页面。

第 4 项是上述页面交互的配套行为。本轮不做首页信息层级改版。

旧计划中“倒计时不设独立页面”的描述属于历史决策；本轮以当前独立 Study 页面为基线，保留学习页及跨页倒计时/PiP 行为，不将倒计时移回首页。

## 2. 目标与非目标

### 2.1 必须达到

- 某个设置接口失败时，其他模块仍能显示和完成合法操作。
- 首次加载、后台刷新、旧数据、错误、重试和 mutation 反馈使用一致语义。
- 页面切换不遗留重复 timer、listener 或相同资源的并发轮询。
- 学习页不因保留门户挂载而持续请求代理组、设备活动等无关资源。
- 设备名称、策略、连接和流量可从一个详情入口访问。
- 设备修改后的持久化状态与运行时状态分别表达。
- 刷新网页留在原页面；受保护深链接登录后留在原目标。
- 不增加顶层页面数量；保留全部现有入口和有效功能。

### 2.2 不在本轮范围

- 首页健康摘要、拓扑和技术详情的视觉重排。
- 公网健康探测、DNS/HTTPS 耗时诊断、断网时间线。
- 新增路由、DNS、代理分流规则、自动 fail-open 或 Tailscale 能力。
- 设备全量流量计量、长期连接日志或历史持久化。
- 学习目标同步、录制或摄像头媒体能力扩展。
- 重写前端框架、固件、OTA 或三个进程的架构。

## 4. URL 导航与恢复

采用 hash 路由，不要求服务器增加 SPA 路径重写。

- 空 hash 进入首页；未知或非法路径以 replace 方式规范化为首页，不产生重定向循环。
- `#/devices/<device-id>` 打开设备详情；device-id 从现有稳定设备标识生成，统一编码、解析及校验。
- 若使用 MAC，统一大小写和格式；URL 不携带密码、订阅 URL、CSRF 或 viewer token。
- `#/activity` 作为设备列表的兼容别名，以 replace 规范化为 `#/devices`。
- 首次渲染从 URL 解析路由，避免先显示首页再跳转。
- 导航按钮、滑动导航、设备打开/关闭、浏览器前进/后退使用同一 typed route 操作。
- 普通页面导航新增历史记录；同一路由不重复 push；规范化仅 replace。
- 从列表打开详情后，关闭/返回恢复列表筛选和滚动位置；直接打开详情链接时，关闭回设备列表，不能盲目 history.back 离开站点。
- 设备筛选等可分享条件放入经过校验的 hash query；滚动位置仅保存为当前浏览器会话内的视图状态。
- 浏览器刷新恢复页面、详情及 URL 中的筛选，不承诺恢复未保存表单或跨浏览器视图状态。
- 未登录访问受保护页面时，就地显示登录；登录成功继续原路由。401 不将用户送回首页。
- 深链接设备暂不可见时显示“当前未发现该设备”或已有配置摘要；保留返回入口，不伪造在线状态。
- 详情采用桌面侧边抽屉、移动端全屏详情。处理焦点进入、焦点返回、Escape 关闭和可访问名称。

URL 路由变化不能导致 Study 状态无意重建，也不能破坏摄像头现有离开页面、关闭会话和麦克风释放规则。

## 5. 独立资源与错误状态

### 5.1 资源边界

按真实 HTTP 资源建立状态，而非为所有设置继续维护一个成功/失败元组。

至少拆分：

- 网络当前配置。
- 网络 pending/事务状态。
- 代理订阅状态。
- 设备策略与活动快照。
- Tailscale 状态/配置。
- Tailscale peers。
- 仪表盘状态、代理 panel、应用状态等既有读取资源。

设备策略和活动若来自同一个现有 endpoint，保留一个共享资源，不为两个 UI 区块重复请求，也不为了前端拆分而臆造新接口。

相互独立的请求可同时发起，每个结果到达后立即更新对应资源；不能用“全部请求完成才提交”的屏障重新引入阻塞。

### 5.2 状态模型

每个资源至少表达：

- 最近一次成功数据，允许为空。
- 首次加载或刷新中。
- 最近错误。
- 最后成功接收时间。
- 当前请求代次及认证作用域。
- 是否已过期或等待重新确认。

统一组件行为：

| 情况 | 显示 |
| --- | --- |
| 无数据，首次请求中 | 加载占位 |
| 无数据，请求失败 | 当前模块错误与重试 |
| 有数据，刷新中 | 保留内容，显示刷新状态 |
| 有数据，刷新失败 | 保留内容，标记旧数据及最后成功时间 |
| 成功的空结果 | 明确空状态，不当作加载或错误 |
| 未订阅/暂停刷新 | 表达未刷新或最后更新时间，不声称实时 |

界面显示“上次成功更新”，不得把请求开始时间或刷新失败时间记成数据更新时间。服务端 observation 时间存在时，须与浏览器接收时间区分；浏览器刚收到旧快照不能被解释为新的运行观测。

### 5.3 mutation 与认证

- busy/error 属于对应操作或模块，不能因订阅刷新锁住 Tailscale 等无关设置。
- 网络配置与 pending 是相关事务：pending 未知时仍可读其他模块，但应禁止依赖已确认事务状态的新网络变更。
- 保留 prepare/apply/confirm/cancel/rollback 和断连后的恢复流程。
- 写入成功后只失效并重读相关资源；不得重新串行加载全部设置。
- 写入成功但回读失败时显示“已保存，状态刷新失败”，不能显示保存失败或假定生效。
- 输入草稿不会被后台轮询覆盖。
- 409/generation 冲突保留草稿、刷新当前服务端配置，要求核对后重试，不盲目重发旧的整表更新。
- 请求取消或旧代次响应不能覆盖新配置、新路由或新的登录状态。
- 401 统一失效认证、清理受保护缓存并停止受保护轮询；保留目标路由。403/CSRF 错误不进行无限登录重试。
- 注销后，旧请求返回不能重新填充设备、网络凭据相关或其他管理员数据。

## 6. 页面订阅与刷新调度

### 6.1 页面依赖

实施时从实际读取点核对依赖，形成可测试的固定映射。

| 页面/场景 | 需要的资源 | 不应自动拉取 |
| --- | --- | --- |
| 首页 | 现有首页显示所需 status/panel | 管理设置、设备活动、peers |
| 学习 | 本地倒计时；确实显示的全局摘要可共享低频缓存 | 订阅、设备活动、代理测速、peers |
| 网络 | 网络配置、pending、必要的网络状态 | 订阅、设备活动、peers |
| 代理 | 代理状态/panel、管理员订阅状态 | 网络编辑配置、设备活动、peers |
| 设备与详情 | 一份设备策略/活动快照，必要的 TUN 生效证据 | 完整网络设置、订阅、peers |
| Tailscale | Tailscale 状态与 peers | 订阅、设备活动 |
| 摄像头 | 现有 camera 状态与会话资源 | 网络编辑配置、订阅、设备活动 |
| 应用/系统 | 当前页面实际显示所需状态 | 无关管理配置和活动 |

全局 shell 若仍显示健康摘要，允许复用同一 status 缓存并低频刷新；不得因此继续全局获取完整 dashboard/panel。某 endpoint 已聚合多个字段时复用现有接口，不声称字段级网络传输已经减少。

### 6.2 调度规则

- 一个资源在同一门户实例中最多一个在途读取请求、一个调度来源。
- 活跃页面订阅资源；无订阅的页面资源取消后续周期刷新。
- 进入页面时立即请求或验证缓存；首次进入必须获取数据。
- 可见页动态状态以现有 `POLL_DELAY_MS` 为初始基线；配置读取以进入页面、手动重试和 mutation 后失效刷新为主。
- 全局摘要建议可见时 30 秒刷新；隐藏时普通观测资源降到不短于 60 秒，允许无消费者资源完全暂停。
- visibility 从 hidden 变为 visible 时，对当前所需资源立即刷新一次；与 focus、online、路由变化触发合并，防止请求风暴。
- 失败采用有上限的退避；手动重试和回到前台可触发一次即时重试。
- 对慢请求不得并发堆积；使用取消或请求代次丢弃过时结果。
- 所有时间间隔集中定义，测试使用可控时钟；浏览器后台 timer 节流意味着实际间隔可能更长。
- 生命周期结束移除 timer 和 listener，快速切页不会积累后台任务。
- 普通轮询绝不触发节点测速、订阅刷新等 mutation；这些操作只由明确用户动作触发。

上述数值为初始调度默认值，实施时可依据既有请求成本调整，并在 PR 中记录最终值及请求计数证据。

### 6.3 必须单独处理的生命周期

- 网络 pending 回滚以服务端事务与 deadline 为准；隐藏页面或暂停轮询不能取消回滚，回到前台先重新确认状态。
- Camera 会话续期、清理、媒体及对讲不能机械套用普通设置轮询降频。
- Study 倒计时按绝对目标时间校正，不能按 timer tick 累减而在后台走慢；保留原有 PiP 生命周期。
- 缓存无新数据时，全局更新时间不能被其他无关资源更新带动。

## 7. 设备列表、详情与策略

### 7.1 列表与详情

设备列表整合现有客户端、持久策略条目和有界活动记录，按稳定设备标识去重。已配置但不在线的设备仍可管理；活动中有记录不等于此刻在线，未知身份不强行归属。

列表展示设备名、必要的 IP/MAC、当前配置策略、可确认的在线状态与流量摘要。详情集中展示：

- 名称与标识。
- 当前配置策略及运行时状态。
- 名称、策略编辑和清除自定义配置。
- 当前连接、近期连接、规则与出口。
- 已观测上传/下载流量及数据更新时间。

流量统计固定标明“仅统计经过 Mihomo 的 LAN 连接；包含有界近期记录”。绕过 Mihomo 的设备无记录时，不得渲染为“没有上网”或“总流量为零”。

汇总按 connection ID 去重，当前与历史记录不重复相加；不把连接持续时间当作请求延迟。不新增长期历史或未被后端实际测量的设备总流量。

### 7.2 策略语义与生效状态

沿用已有 `Direct / Proxy` 契约：

- Direct：设备绕过 Mihomo TUN。
- Proxy：使用 Mihomo 分流规则，仍可能按国内规则 DIRECT，不是强制全部访问走机场。

界面可使用“直连 / 按规则分流”以减少歧义，wire 枚举保持不变。

| 证据 | 用户反馈 |
| --- | --- |
| 写请求失败 | 保存失败，保留草稿 |
| 写请求成功，尚未确认运行状态 | 已保存，生效状态待确认 |
| 配置已保存，已确认全局 TUN 未启用 | 已保存，等待启用 TUN |
| TUN 请求开启但状态异常/未知 | 已保存，透明代理未就绪或生效状态待确认 |
| 当前保存版本已经由运行态明确应用 | 已生效 |

现有 snapshot 包含 config generation 与 effective；实施前必须追踪 effective 的后端定义，确认它是否证明“当前配置代次已应用”。不能只看到 TUN 开启或 POST 200 就报告设备策略已生效。

优先复用现有证据；若现有契约不足以证明应用代次，使用“已保存，生效状态待确认”。需要新增后端观测字段时，先记录缺口和最小契约方案，不在本前端计划中夹带 router/wire 重构。

策略只影响适用的新连接，不能承诺已有连接立即迁移或中断。网络语义遵循现有产品实现。

## 8. 实现边界与代码组织

延续 `adapters -> application -> domain` 边界。Web 只通过 typed HTTP API 访问门户，不依赖 native adapter、Unix socket 或 Linux 命令。

建议按实际职责渐进增加：

- 路由解析与导航模块。
- 资源状态与请求协调模块。
- 可见性/轮询 hook。
- 设备列表与设备详情组件。
- 统一资源加载、错误与更新时间组件。

root App 只负责 composition、路由、认证及真正共享资源；不能把新状态再次堆成单一全局 mega-state。无需引入通用复杂查询框架，也不预先建立空目录树。

保留 exact Origin、CSRF、请求体上限、认证、敏感信息不回显、anonymous camera viewer 与管理员设置边界。受保护深链接不能绕过 API 权限。

## 9. 分阶段实施

功能分支建议：`feat/web-page-data-and-devices`。整轮通过一个 PR 交付，按可审查的阶段提交；不为每个测试循环分别 push。

### 阶段 A：基线与导航

- [ ] 核对当前 main、AGENTS、API/DTO 语义及现有 E2E。
- [ ] 记录现有请求来源和页面挂载/隐藏机制。
- [ ] 先补路由解析、刷新恢复、历史导航、登录后保留目标的失败测试。
- [ ] 实现 typed hash route，接入按钮与滑动导航。
- [ ] 验证 Study/PiP、Camera 离页行为不回归。

### 阶段 B：独立数据与错误

- [ ] 拆分 settings 聚合结果及全局 settings busy/error。
- [ ] 独立模块加载、重试、草稿与最近成功数据。
- [ ] mutation 后按资源失效刷新，处理旧响应、409 与认证失效。
- [ ] 将订阅表单迁入代理页。

### 阶段 C：刷新调度

- [ ] 建立页面资源依赖与共享请求去重。
- [ ] 加入可见性降频、恢复即时刷新、失败退避与清理。
- [ ] 移除原全局 dashboard 和活动页的重复周期请求。
- [ ] 统一模块更新时间，验证网络 pending/Camera/Study 例外。

### 阶段 D：设备交互与收尾

- [ ] 活动导航改为设备，整合列表与策略条目。
- [ ] 实现桌面抽屉、移动全屏详情及 URL 深链接。
- [ ] 接入名称、策略、清除、手动添加 MAC 和精确保存反馈。
- [ ] 保留筛选/滚动，核对流量统计范围。
- [ ] 完成相关回归、请求计数证据、文档和 PR 说明。

每个行为遵循 Red → Green → Refactor。页面变化同步更新用户行为断言，不以删除测试、放宽安全断言或固定 sleep 解决异步失败。

## 10. 验收矩阵

| 场景 | 通过标准 |
| --- | --- |
| 订阅请求 500 或持续延迟 | 网络/设备/Tailscale 已加载内容与独立操作可用 |
| Tailscale peers 失败 | Tailscale 本身状态及其他页面可用，peers 局部重试 |
| 网络 pending 读取失败 | 错误局部显示，相关危险变更禁用，无关模块可操作 |
| 首次加载与刷新失败 | 无数据错误和带旧数据错误可区分，成功时间不虚增 |
| 保存成功、回读失败 | 明确已保存及状态未知，不误报保存失败 |
| 连续快速切页、慢响应 | 请求不重复积累，旧结果不覆盖新状态 |
| 两个区域读取设备快照 | 同一资源只发一份请求 |
| 浏览器隐藏/恢复 | 计数证明降频；恢复触发一次所需刷新 |
| 学习页停留 | 无设备活动/订阅/peers/测速请求，倒计时正确 |
| 409、注销与 401 | 草稿/目标页面行为明确，不泄漏缓存，不盲目重试 |
| 设备 Direct、TUN 关闭、运行态未知 | 保存和生效文案与证据一致 |
| 空活动、设备离线、重复连接记录 | 不虚构在线/总流量，统计不重复 |
| 设备编辑后关闭详情 | 列表更新，筛选与滚动位置保留 |
| URL 深链接及刷新 | 留在原页面/详情，非法路由安全规范化 |
| 浏览器前进/后退、滑动导航 | URL 与页面一致，无重复历史和循环 |
| 移动端详情与桌面抽屉 | 操作不遮挡、焦点可控、键盘可退出 |
| 网络 apply/confirm/rollback | 事务与自动回滚行为保持 |
| Camera、对讲、Study PiP | 原有跨页/释放/计时行为保持 |
| 订阅迁移与旧活动入口 | 原功能在新位置可达，旧 hash 可恢复 |

测试优先使用现有 loopback harness、fake ports、可控响应和时钟。E2E 以 role、label、可见反馈、URL 与网络请求数量断言用户行为；避免依赖 CSS class、DOM 顺序或真实 WAN。
