# hyz-image-ocr

## 何时使用

- 先直接查看用户本次消息附带的原图。只有存在识别歧义或版面复杂时，才调用本 Skill：
  - 数字、运算符、分数线、上下标、圈画或中文手写存在歧义；
  - 多栏、双栏排版；
  - 多道试题混排；
  - 题干与选项交错；
  - OCR 阅读顺序异常；
  - 手写文字与印刷文字混排；
  - 需要逐字核对大段印刷文字。
- 清晰、简单、可直接读出的图片不要重复 OCR。
- OCR 是辅助证据：必须回到原图核对；用户速算过程、合理近似和不确定符号不擅自改写。若两者冲突，明确报告歧义。
- 普通 OCR 不等同于数学公式识别；不要假定它能稳定生成 LaTeX。

## 调用方式

只接受本次上传的原图，路径必须位于当前项目：

```text
<项目根>/tmp/hyz-ai-uploads/<uuid>.png
<项目根>/tmp/hyz-ai-uploads/<uuid>.jpg
```

在该项目根目录执行：

```bash
python3 .agents/skills/hyz-image-ocr/scripts/ocr_client.py \
  tmp/hyz-ai-uploads/<uuid>.png
```

- 成功时输出 JSON：

```json
{
  "ok": true,
  "lines": ["第一行文字"],
  "blocks": [
    {
      "id": 0,
      "page": 1,
      "text": "第一行文字",
      "confidence": 0.96,
      "box": [12, 43, 250, 81],
      "polygon": [[12, 43], [250, 43], [250, 81], [12, 81]]
    }
  ]
}
```

- `lines` 保持旧调用兼容：按原始顺序输出去重后的非空文字。
- `blocks` 与 OCR 服务返回的文字数组严格同序，保留重复文字；`id` 在整个响应内唯一，`page` 从 1 开始。
- `box` 是 `[x1, y1, x2, y2]` 轴对齐矩形；`polygon` 是文字区域四边形坐标。字段缺失或数值无效时为 `null`，不会用其他文字块的字段补齐。
- 默认不输出完整 `raw`，避免把大量原始 JSON 重复送给模型。排查服务返回结构时加 `--raw`。
- 失败时输出 `{"ok": false, "error": "..."}` 并以非零状态退出；此时直接说明 OCR 不可用，继续按原图给出不确定标注。
- 脚本固定请求本机 `http://127.0.0.1:8080/ocr`，可用 `HYZ_OCR_URL` 覆盖为同机 loopback 端口。它不访问网络、不执行图片内容，也不接受外部 URL。
- 不要读取 `tmp/hyz-ai-uploads/` 以外的文件；不要尝试安装依赖、启动服务、执行 sudo、修改服务配置或把原始图片复制到别处。

## 阅读顺序与复杂版面

- `blocks` 的顺序是 OCR 服务的原始返回顺序。多栏版面可能按全局 Y 交错（例如左栏第一行、右栏第一行、左栏第二行），它不是可靠的阅读顺序。
- 不要简单地按全局 Y 坐标排序来“修正”顺序，也不要自行重排 `blocks`。应结合原图、`box`/`polygon` 坐标、栏边界和文字语义判断阅读顺序。
- 多题混排时，先按版面分栏、分题，再判断题内顺序；题干与选项交错时，用坐标和语义确认归属。
- 不得仅根据语义补全、修改或重写题干、选项和材料；OCR 只提供识别证据。
- OCR 与原图冲突时，以原图为准；无法确认的内容明确标记为不确定。

## 维护与诊断

宿主机安装、systemd --user 单元和卸载步骤见 `scripts/ocr-host/README.md`。服务不可用时只报告状态，不自行修复。
